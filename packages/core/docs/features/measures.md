# Weights, measures and money

`src/Measures/` marks the weights, measures, coins and times of day the Bible names (cubits, shekels, ephahs, pence, the ninth hour, the fourth watch) and explains each in the reader's own units in a popup. It is a built-in core feature in the `@bible/core/browser` barrel (task 0069); the desktop and web apps add only the wiring.

## Data

| File | Purpose |
|---|---|
| `src/Measures/data/units.json` | The unit registry: dimension, SI value with an uncertainty range, relations ("1 cubit = 2 spans"), wages and metal for coins, clock times for hours and watches, Strong's numbers, source ids. |
| `src/Measures/data/sources.json` | Citations (ABD, NIDB, ISBE 1915, Easton, Smith). Values are facts from published scholarship; note text is written fresh. |
| `src/Measures/data/occurrences/{ot,nt}.json` | One row per measure in the text, keyed by KJV verse id: units and quantities exactly as the KJV states them, `usage` (`literal`, `illustrative`, `figurative`), anchor hints and `review.status`. One row per line, so review diffs stay small. Loaded lazily per testament. |
| `src/Measures/data/locales/<lang>.json` | Unit names, the text's own words (`textNames`, e.g. "mites" for lepta), match terms, notes and phrase templates (en, es, zh-Hans). `en.verses.json` holds verse notes. |
| `src/Measures/__fixtures__/kjv-measure-verses.json` | KJV words and interlinear spans of every verse with a row; the data test proves each row anchors on a unit word. |

The rows are generated by the measures builder (build-occurrences.mjs) in the bible-scripts repository from a Strong's-tagged KJV module plus a curated `overrides.json`, and re-running it keeps reviewed rows. **Only reviewed or approved rows are shown.** Draft rows appear only with the `measureDrafts` feature flag (review and development).

## Code

| File | Purpose |
|---|---|
| `types.ts` | `MeasureUnitDef`, `MeasureOccurrence`, `MeasureLocalePack`, `MeasurePreferences`, `MeasurePopupModel`. |
| `registry.ts`, `locale.ts` | Registry and locale-pack lookup with English fallback (terms never fall back across languages). |
| `prefs.ts` | `MEASURE_SETTINGS` (settings group `measures`) and `resolveMeasurePreferences`: unit system defaults by region (US, LR, MM: US customary + metric; GB: metric + imperial for length and mass; else metric), display `off` (default: conversions live in the Study panel only) / `marker` (underline and popup) / `inline` (plus the conversion in [square brackets]), Reading mode off unless opted in, money as wages / metal / both, optional modern daily wage, clock, ranges. |
| `convert.ts` | Conversion, display-unit choice, 2-significant-figure rounding, ranges, wages scaling (minutes to years), clock formatting. |
| `anchor.ts` | `resolveMeasureAnchors`: Strong's (interlinear) first, then the module language's terms, then modern terms after a number ("450 feet"), else the verse. Also finds `phraseEnd`, the last word of the whole phrase ("two cubits and a half", "a cubit and a span"), from the module language's `grammar` (connectors, articles, fractions); an inline conversion goes after it, or after the unit word when the phrase cannot be resolved. |
| `layer.ts` | `buildMeasureLayer`: a `core::measures` decoration layer (dotted accent underline, optional value badge, a ⚖ badge on the last word for verse-level fallbacks) and `MeasureIndex` (verse id + word index to occurrences). |
| `popup.ts` | `buildMeasurePopup`: the localized popup model. |
| `chapter.ts` | `computeChapterMeasures`: one call for apps, like keyword marks' chapter helpers; `computeVerseMeasures`: one verse's models for the Study panel (no verse text needed). |

`@bible/ui`'s `MeasurePopup` renders the model; apps put it in a `Popover` (hover after 300 ms, click pins) or, on phones, a `BottomSheet`. Preferences are app settings (web: localStorage; desktop: session preferences), not user data.


## Translation readiness

No English lives in the logic: phrase templates (`phrases`, including the `[about {value}]` inline form), unit and modern-unit names, number words and the phrase `grammar` are all in the language packs (`data/locales/<lang>.json`, English being the fallback pack). A language is added by adding a pack; the apps' UI labels go through their own i18n.
