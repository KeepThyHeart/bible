# Keep Thy Heart Bible Reader 1.0.0-rc.1: release notes

Paste the "Upgrading" section into the GitHub release body (the workflow drafts the release with `--generate-notes`).

## Upgrading from 0.1.0-beta.1

Your notes, highlights, bookmarks, settings, layout and modules are kept: they live in your user profile, not in the
app folder, and 1.0 opens the same profile.

- **Windows:** run the new installer, or use the in-app update. It replaces 0.1.0-beta.1 (one entry stays in
  Settings > Apps). If you pinned the app to the taskbar, unpin it and pin it again: the app's Windows identity changed.
- **macOS:** download the new `.dmg` and drag the app into Applications, replacing the old one. The in-app update
  cannot install this release. You may be asked to allow keychain access ("Safe Storage"; choose Always Allow) and to
  allow notifications again.
- **Linux:** install the new `.deb` over the old one (`sudo apt install ./keep-thy-heart-bible-reader_1.0.0-rc.1_amd64.deb`),
  or replace the AppImage.

## What changed in the app's identity (for maintainers)

The desktop app id moved from `com.bibledesktopapp.app` (beta.1) to `com.keepthyheart.bible.desktop`.

| | Effect |
|---|---|
| Windows installer | The NSIS GUID is pinned to beta.1's (`d159dead-52c2-56b9-8a81-6c170917f41d`) for official builds, so the installer finds and replaces beta.1, honours a custom install folder and keeps one Apps entry. |
| Windows AppUserModelID | New, so old taskbar pins go stale (re-pin). Start-menu shortcuts are recreated with the new id. |
| macOS bundle id | New: notification permission is asked again; the old `~/Library/{Preferences,Caches,Saved Application State}/com.bibledesktopapp.app*` files are left behind (harmless). Squirrel cannot update an ad-hoc signed beta.1, so Mac users download 1.0 by hand. |
| Linux | No effect: the deb package name, AppImage name and `.desktop` file come from the product name. |
| User data | Unchanged on every OS: Electron's `userData` follows the package name (`@bible/desktop`), not the app id. A test pins this. |

The app id should not change again once builds are signed: a new id breaks the macOS update chain and orphans the Windows login item.

## Not in 1.0

- Scripture memory's "Recite aloud" and hands-free mode are hidden (feature flag `recite`, off by default); they return with the recite engine.
- Web accounts.
- Languages other than English are labelled "Preview" (machine-drafted, not yet reviewed).
- The extension API and SDK are experimental and may change.
